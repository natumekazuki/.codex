# Subagent Review Boundary

委譲前に読む。汎用`general_astra`、`general_sol`、`general_luna`には、対象、必要な結果、権限を依頼ごとに渡す。調査だけの依頼では編集しない。履歴継承に頼らず、review依頼には主要動作、後続の依存、[開発・review・統合](../guides/development.md)の統合基準と、非ブロッカーを全件修正待ちにしないことを含める。必要な参照先は参照元文書から解決した実pathで渡し、全規約を無条件に複製しない。

共有する設計判断に関わる依頼では、必要な要求・前提、採用済みの判断と適用状況、未合意事項、[設計判断・文書化](../guides/design-decisions.md)の参照先も渡す。同じ前提の判断を再利用し、現行実装や草案を採用根拠に置き換えない。不足の調査・推奨案・草案作成までを依頼できるが、親からの委譲を未合意方針の採用や操作権限の拡大と解釈しない。

使用modelは`gpt-6.1-sol`、`gpt-6-luna`、`gpt-6-astra`のみ。公式情報、設定値と採用理由は[README](../../README.md#modelとrole)に記載する。

- GPT-6.1 Solを通常の親と一般childの既定とし、調査、設計、実装、debug、reviewを担当させる。
- Lunaは、進め方・手順・期待結果がほぼ決まっている抽出、定型調査、設計済みの実装、判断済みの基準に沿った照合等へ割り当てる。範囲が小さいことだけで選ばず、未解決の設計・安全性の判断を押し込まない。
- Astraは、高度な判断が要求される設計の選択、契約間の矛盾の解消、難しい反例の検討等を、非Astra親から必要な問題に絞って渡す場合に使う。Astra親はその判断を自ら担当し、Astra→Astraは禁止する。

上位modelの選択に下位modelの失敗を要求せず、作業に必要な判断で直接選ぶ。下位modelの形式的な試行、念のための多重reviewは不要。専門審査の手順と必須条件は該当Skillに従い、役割不足や未解決事項があれば親が必要な追加context・担当を判断する。modelの変更を審査免除や権限拡大に使わない。

指定modelがruntimeで利用できない場合、許可された構成の親で可能な範囲を続け、必須の委譲を実施できない時はその条件を報告する。role名だけで実modelを推測せず、起動するsessionのmodel IDとeffortを確認する。履歴継承はhookで`none`に固定されるため、対象・必要な文脈・完了条件を起動時の依頼へ含める。

`wait_agent` を呼ぶたびに、`timeout_ms` には完了までの推定残り時間の2倍をミリ秒で明示する。ツール定義の最短・最大待機時間の範囲に収め、見積もれない場合は既定時間を明示する。通知で途中解除されるため、短い確認のために待機時間を縮めない。タイムアウト後は完了見込みを更新して同じ基準で待つ。

test価値reviewの抽出、read-onlyサブエージェントへの委譲、review観点、完了判断は[review-test-value](../../skills/review-test-value/SKILL.md)を正本とする。専用roleや独自のworker、scheduler、artifact storeは使わない。

同じworking treeで作業する場合は編集範囲と生成物の競合を避け、ユーザーと他の担当の変更を保護する。子は結果、根拠、実行した確認、未解決事項を親へ返し、親が統合と最終確認を行う。通常の成果返却に専用文書は不要である。

worktreeやcommit固定は具体的な隔離・再現の必要に応じて使う。全reviewへ一律に別worktreeを要求しない。

非ブロッカーは上記の統合基準に従って別の修正タスクとして扱い、その着手・完了を現在の変更の完了・統合条件にしない。
