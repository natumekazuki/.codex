# natumekazuki/.codex v5.0.0

review-test-valueの一対多置換を旧新recordを保持して審査できるようにし、Memory・Character Affectの利用方針と、レビュー指摘の仕上げ・後追い判断を更新しました。

## 破壊的変更: 一対多置換のGit差分選択

- [Git差分選択の契約](https://github.com/natumekazuki/.codex/blob/77877ab1da4547dbb200409f94ffe396c3585e97/skills/review-test-value/references/git-selection-v1.md)に定める一対多置換では、従来の`RECORD_TRANSITION_UNRESOLVED`による停止から、旧recordの`DELETED.before`と各新recordの`ADDED.after`を保持した抽出成功へ変わります。
- 旧開始行の置換、保持行の複数の未対応新宣言への分散など、契約の条件を全て満たす場合だけを対象とします。内容・位置の候補が競合する場合、不正metadata、宣言外への投影、解析失敗等の停止を一律に抑制するものではありません。
- [回帰test](https://github.com/natumekazuki/.codex/blob/77877ab1da4547dbb200409f94ffe396c3585e97/skills/review-test-value/scripts/test_extract_test_values_multilang.py)では、旧新の全文・位置・metadataの保持と、working・staged・headの各snapshotの区別を確認します。実装はsymbol名や共通本文から存続を推測しません。
- `DELETED`は機能の廃止承認ではありません。抽出成功も意味上の審査完了ではなく、旧新全recordのread-only価値審査が引き続き必要です。

公開済みのGit選択・失敗契約を変更するため、v4.6.0からmajor versionを更新します。CLI引数、構造化resultのschema、metadata v2、source adapterの形式は変更しません。新しい依存やデータ移行はありません。従来の停止結果を前提とする利用手順は、新しい限定条件と全件審査の扱いを確認してください。[ADR-0021](https://github.com/natumekazuki/.codex/blob/77877ab1da4547dbb200409f94ffe396c3585e97/docs/adr/0021-git-diff-test-value-selection.md)には変更した適用範囲を明記しています。
