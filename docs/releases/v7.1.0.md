# v7.1.0

子Sessionの作業領域分離と親の準備・回収責務、委譲文面の規定を追加します。

## 変更内容

[委譲ガイド](https://github.com/natumekazuki/.codex/blob/09d1dfd75003777c9d6c052b7b1b7250c6812cb8/docs/architecture/subagent-workspace.md)で、通常のMain Sessionを役割を問わず1 Session・1専有Workspaceとし、同じ作業directoryを複数のSessionへ重複割当しません。Git管理下の通常子にはreviewを含めて専用Worktreeを割り当て、同じrepositoryでの並行作業は別branchで行います。Auxiliaryとnativeサブエージェントは対象外とし、既存の編集所有・衝突回避・権限を保ちます。子を起動する直接の親が、起動前にその子の専用領域を作成・確認して絶対pathを渡します。準備に失敗したら子の起動を保留し、親のWorkspaceを代用しません。旧規定「全体統括は実際のGit操作を担当へ委譲する」を置き換え、領域の準備・回収を統括の直接操作に含めます。

作業領域は同じSession・同じ担当作業で再利用し、待機・中断・修正待ちの間は保持します。親は成果の受入と必要な統合の後に、実行中・予約済み作業と他Session利用の不在、成果・資料の保全、残すべき未コミット・未追跡・ignoredデータの確認を経て回収します。Worktreeとbranchは別々に回収でき、通常削除の拒否からforceへの自動切り替えはせず、回収対象はこの運用で新規に作った子用Worktree、ローカルtask branch、非Git専用領域に限ります。既存Worktreeは他Sessionの占有を確認してから割り当て、forceで同じbranchを複数checkoutしません。Git管理外の作業では、親が専用directoryへ必要な入力だけをコピーし、子は原本を直接編集しません。親が原本の現在状態と対象を確認して必要な成果だけを反映します。割当Workspaceの不在で子Sessionへの送信が拒否された場合、送信元Sessionが復旧を担います。

[協同ガイド](https://github.com/natumekazuki/.codex/blob/09d1dfd75003777c9d6c052b7b1b7250c6812cb8/docs/guides/withmate-collaboration.md)と[AGENTS.md](https://github.com/natumekazuki/.codex/blob/09d1dfd75003777c9d6c052b7b1b7250c6812cb8/AGENTS.md)で、依頼・追加指示は受け取った意図を整理し、目的・担当範囲・必要な成果・契約・権限を親自身の言葉で伝える規定を追加します。ユーザー発言の転載や言い換えだけで依頼を済ませず、原文を扱う作業では依頼と資料を分けてコード・ログ・指定文言など正確さが必要な資料を改変しません。

## 互換性・更新時の注意

指示と運用ルールの追加・置き換えです。新しい必須ルールの追加を含むためminor versionを更新します。Skill名・配置入口、`review-test-value` のCLI・result・metadata・adapter・Git差分選択、通常Session履歴、Graph・Glossaryの契約、操作承認・データ保護は変更しません。`session.resolve_worktree` の取得契約、配布構成、`~/.codex/` への配置手順も維持します。管理台帳や恒久testは新設しません。既存homeへは対象文書の差分を反映し、実設定・認証・履歴等を上書きしないでください。
