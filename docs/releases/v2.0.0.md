# natumekazuki/.codex v2.0.0

互換性境界や残件管理先の不足による一律の実装着手停止を、変更が影響する保護対象と引継ぎに依存する範囲の判断へ変更しました。

## 変更

- 維持対象の不足・矛盾が変更可否を左右する場合は、その判断に依存する変更を止めます。実際の差分と依存先から独立性を説明できる作業は進め、未調査を安全の根拠にしません。
- Gitリリースタグは版の識別手段とし、タグが指す実装・UI全体を互換維持対象にしません。タグなしのRC・STGを含め、保持データ、適用済みmigration、業務上の確定結果、認証・認可、利用中の外部契約は実際の適用状況に応じて保護します。
- 画面配置・文言・入力手順等は、保護対象を損なわなければ改善できます。UIが担う業務承認、実行前確認、情報公開範囲等は変更影響を評価します。
- repository内Markdownも残件の正式な管理先として扱えます。管理先が未定義でも残件を伴わない独立変更は一律に止めず、残件の登録が必要な場合は管理先を確定して登録するまで引継ぎ・統合を完了扱いしません。
- 共通`AGENTS.md`、開発・設計判断のguide、配布元READMEの検証例、hookの再通知を同じ判断に揃えました。

## 互換性

- `v1.2.0`で維持した「管理先または互換性境界が未定義なら実装変更を開始しない」条件を廃止するため、共通作業規約の破壊的変更としてmajor versionを上げました。
- `review-test-value`のCLI・構造化result・metadata v2・対応adapter・Git差分選択の契約は変更していません。データ破棄や適用済み環境の再作成、外部write等の承認条件、必須確認、accessibility、データ保護も維持します。

## 検証

- 現役の共通文書とhookに旧一律停止の文言が残らないこと、および配布元READMEの変更影響別の判断例との整合を確認しました。
- PowerShell hookの直接実行によるsmoke testと、対象差分の`git diff --check`は成功しました。
- 実環境への配置、新規sessionでの読込・行動確認、PRのCIは未実施です。
