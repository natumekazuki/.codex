# natumekazuki/.codex v4.6.0

review-test-valueに、直比較の遷移を確定できない場合の正式な統合履歴審査経路を追加しました。[Issue #120](https://github.com/natumekazuki/.codex/issues/120)への対応です。

## 変更

- [Skillの実行手順](https://github.com/natumekazuki/.codex/blob/0394ce36a4f5d2e60d8953d845e933fb052d5302/skills/review-test-value/SKILL.md)から、直比較が `RECORD_TRANSITION_UNRESOLVED` だけで停止した場合に、同じtask baseを保持した別経路を選べるようにしました。
- [Git差分選択の契約](https://github.com/natumekazuki/.codex/blob/0394ce36a4f5d2e60d8953d845e933fb052d5302/skills/review-test-value/references/git-selection-v1.md#統合履歴による審査)に、first-parentの全隣接区間を既存CLIで抽出し、全record・transitionを独立審査する手順を追加しました。working tree／indexを対象にする場合は、固定したHEADからの終端差分も含めます。
- 削除前の `DELETED.before` と再追加の `ADDED` を別々に保持し、共通本文やsymbol名から存続を推測しません。全区間の成功が必要であり、途中の曖昧な遷移・不正metadata・解析失敗を後続の正常snapshotで免除しません。
- [回帰test](https://github.com/natumekazuki/.codex/blob/0394ce36a4f5d2e60d8953d845e933fb052d5302/skills/review-test-value/scripts/test_extract_test_values_multilang.py)に、意味のある共通本文が複数宣言へ投影される停止形と、削除・再追加履歴の証拠保持、途中commitの不正metadataを追加しました。

## 互換性と適用

互換性を保った審査経路の追加としてminor releaseにします。`@test-value v2`、CLI引数、result schema、source adapter、直比較のGit選択・失敗契約は変更しません。新しい実行基盤や依存は追加しません。

元baseがfirst-parent鎖上にない場合や、必要な履歴がない場合は、この経路を使えません。mergeは第一親から統合結果への全変更を扱い、side branch内部だけの途中状態は対象外です。単一区間の中で対応が曖昧な場合も停止します。履歴を改変したり、成功する区間だけを選んだりする手順ではありません。

配布物の取得だけでは端末localのSkillは更新されません。既存の実設定・認証・Memory・共有記録を保持し、必要な差分だけを配置してください。
