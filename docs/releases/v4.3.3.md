# natumekazuki/.codex v4.3.3

Windowsのhook起動コマンドで、外側PowerShellが内側の変数を先に展開して起動に失敗する不具合を修正しました。

## 変更

- [hooks.json](https://github.com/natumekazuki/.codex/blob/01dc99fd02be75c0e1a2fcfd92130652c2c35514/hooks.json)の全4件の`commandWindows`で、環境変数を`Environment.GetEnvironmentVariable`から読み取ります。コマンド本文に変数展開を含めず、cmd・PowerShellの両方から起動できる形式にしました。
- [Windows回帰確認](https://github.com/natumekazuki/.codex/blob/01dc99fd02be75c0e1a2fcfd92130652c2c35514/hooks/test-windows-launch.ps1)を追加し、[既存CI](https://github.com/natumekazuki/.codex/blob/01dc99fd02be75c0e1a2fcfd92130652c2c35514/.github/workflows/ci.yml)で設定内のコマンドとstdin契約を確認します。script本体の直接起動だけでは見逃す二重展開を回帰対象にしました。

## 互換性と更新

- hookの既存契約を維持するpatch releaseです。UserPromptSubmit、SubagentStart、SessionStart、PreToolUseのイベント・matcher、generic command、出力・stdin契約、model制約、`fork_turns`制御は変更しません。
- CODEX_HOME未指定・空・空白の場合はUSERPROFILE直下の`.codex`、指定時はそのpathからhook scriptを解決します。空白を含むpathにも対応します。既存5秒のtimeoutを維持し、新しい依存・設定・データ移行はありません。
- 既存の配置方法で`hooks.json`を更新してください。変更されたhook定義はユーザーによるtrust再承認が必要です。hookの無効化や承認状態の書き換えを回避策にしません。
- 配布元の公開と利用環境への配置は別です。利用側の実config・認証・無関係な変更は上書きしません。

## 検証と確認範囲

- 修正commit `01dc99fd02be75c0e1a2fcfd92130652c2c35514`で、Windowsの回帰46件が成功しました。cmd・pwsh、全4件のコマンド、CODEX_HOME未指定・空・空白・空白を含む指定pathを確認しています。
- 通知stdoutが同じshellによる直接script実行とbyte単位で一致すること、PreToolUseの許可・拒否、許可model、Astra親からのAstra起動拒否、`fork_turns: none`への変更とその他の引数保持を確認しました。
- 修正前コマンドのPowerShell経由でのexit 1を再現し、Windowsコマンド以外のhook設定が変更されていないこと、差分check、対象差分の確認が成功しています。
- GitHub CIのWindows・Linuxの結果は、PRとmain統合後の各実行記録で確認します。ローカル回帰の成功をCI実行済みの証拠とは扱いません。
- 利用側への配置、trust再承認、Codexの実hookイベントによる再通知は未確認です。上記は対応するshell経由のコマンド起動であり、実イベントのend-to-end確認ではありません。SessionStartの実イベントでの5秒timeout解消も未確認で、同じ原因と断定しません。
