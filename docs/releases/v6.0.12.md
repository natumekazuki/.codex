# v6.0.12

WithMate v6.5.0-preview.3のSession Graph契約に合わせ、担当・由来・更新・関係取得の利用方針を修正しました。[Codex Issue #135](https://github.com/natumekazuki/.codex/issues/135)の対応です。

## 変更内容

- [Session Graph Skill](https://github.com/natumekazuki/.codex/blob/589e604564b4527288734d2ac500dfb646b6df1e/skills/session-graph/SKILL.md)で、担当actorを信頼済みbindingから解決し、内容のorigin、採否判断のadoptionOrigin、任意のactorRole、担当snapshot、初回記録者recordedByを区別しました。ユーザー採用や別担当の通常更新で帰属を付け替えません。
- 必須本文の更新と、任意属性の省略保持・null解除を分けました。kind変更時の不要状態と、採否変更時の既存adoptionOriginを明示的に扱います。
- 保存するすべてのreferencesを絶対file pathまたは完全な対応URLとし、相対pathの例外や同名fileの探索を追加しません。
- 意味のあるrelationをrecordと同じatomic applyへ明示し、stable IDによる更新とremoveRelationIdsによる解除を使います。recordとは独立したrelation paging、同じrevisionでの継続取得、表示外endpoint要約の限界を明記しました。
- [READMEの配置後の確認観点](https://github.com/natumekazuki/.codex/blob/589e604564b4527288734d2ac500dfb646b6df1e/README.md)も新しい更新契約へ合わせました。

## 互換性

既存Skillの互換修正です。操作・schema・状態・上限・認可の正本はruntimeの提供契約とし、旧actor自由labelや全属性置換の指示は残しません。

復元順序、要求の先行記録、CAS競合・保存応答喪失時の扱い、背景用途のread-only、Character表現の適用境界、review結果の正本、操作権限は維持します。Skill名、hook、model・接続設定、コード・testは変更しません。既存Graph・Memory・認証・カスタム指示を保護し、移行・一括変換・独自storeの追加は行いません。

## 確認

- 稼働WithMate.exeの版が6.5.0-preview.3であり、今回のprovider turnに新契約のMCP schemaが提供されていることを確認しました。
- [WithMateの固定source](https://github.com/natumekazuki/WithMate/tree/2b1fda1fb268708e849b8da270c74d752209fe3b)を使い、実データと分離したSQLiteで11ケースが成功しました。production SDK MCP／CLI関数entry、runtimeのbinding・active turn、application service、SQLite storageを通して保存結果を確認しています。
- 対象は新規作成、同じCharacterの別Sessionによるユーザー採用・通常更新、省略保持/null解除、kind・採否の遷移、絶対参照と相対参照拒否、relationの登録・endpoint更新・削除、401件の400＋1 paging、表示外recordの明示取得、CAS競合後の復元、置換前本文保持です。
- 更新後Skillを読む独立した新規担当の実利用確認と、3者それぞれのSkill形式検証を分けて実施しました。親担当も隔離SQLiteをread-onlyで読み直し、帰属・由来・解除・本文保持・関係件数を照合しました。
- 3者の該当方針、変更差分、差分check、固定commitの参照先を確認しました。

## 確認限界

Main／Auxiliaryは隔離fixture内の模擬Sessionです。新規担当によるSkill実利用は確認しましたが、3製品それぞれの新規host SessionでのSkill発見、HTTP通信・credential discovery、OSプロセス版CLI、配備desktop/UI、参照先の実在性は未検証です。形式検証や分離fixtureの成功を、これらの実動作の確認とは扱いません。
