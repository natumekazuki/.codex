# natumekazuki/.codex v1.2.0

課題・対応予定・リリース運用について、各プロジェクトが定義する観点とCodexの共通判断原則を整理しました。

## 変更

- 共通`AGENTS.md`は常時必要な原則と条件付き参照の入口にとどめ、課題管理だけの依頼やリリース範囲の確定時にも、共通guideと対象repositoryの運用文書を読む条件を追加しました。
- `docs/guides/development.md`に、課題管理先、対応予定、コード・公開単位、互換性境界、完了・公開、予定変更、判断と操作の権限の観点を集約しました。対応予定と実装反映・検証・公開を分け、Milestoneの採用は必須としません。
- 対象予定の未完了課題と、今回の対象になり得る予定未指定課題をリリース範囲の確定・公開判断時に確認します。未指定や同一予定単位の非ブロッカーだけで実装・統合を一律に停止しません。
- `README.md`、正本案内、hookの現役の参照を更新しました。配布元固有のIssue管理先・リリース境界は他のプロジェクトへ適用しません。

## 互換性

- `v1.1.1`の`review-test-value`のCLI、構造化result、metadata v2、対応adapter、Git差分選択の契約を維持します。
- バグ・後追い残件の管理先と互換性境界が未定義なら実装変更を開始しない既存条件、必須確認、外部操作の承認境界を維持します。新しい管理観点の不足は、その不足に依存する判断・操作だけを保留します。
- 特定プロジェクトのMilestone採用や個々の課題の予定は、この共通ルールのリリースでは決定・変更しません。
