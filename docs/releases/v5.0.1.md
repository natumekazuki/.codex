# natumekazuki/.codex v5.0.1

実装時の過剰な複雑化を抑える判断基準を、既存の開発guideへまとめました。

## 変更内容

[実装の複雑さと責務](https://github.com/natumekazuki/.codex/blob/09b53bc6e5d135f909606d9aeb36e10afd953a1f/docs/guides/development.md#実装の複雑さと責務)に、次の4項目を明記しました。

- 推測的・極低確率の同時実行やセキュリティ上の問題への対策で複雑さを加える前に、失敗条件・発生可能性の根拠・追加負担を説明し、了承を得る。
- 未知の値は責任を持つ信頼境界で検証し、保証が有効な内部経路では同じ検証を重ねない。
- 単発の単純な補助関数を先回りで作らず、再利用・合成・境界の隔離・意味のある命名を根拠に分割する。
- `try/catch`はその場所で必要な回復・変換・記録等を担う場合に使い、不要な再送出や失敗の隠蔽を追加しない。

必要性が確定している安全対策、新たな境界・状態変化に必要な検証、主要な流れを読みやすくする分割は維持します。AGENTS.md、Skill、hookへ同じ本文を重複追加していません。

## 互換性

既存原則の具体化であり、review-test-valueのCLI・構造化result・metadata・source adapter・Git差分選択、およびSession Graphの保存契約は変更しません。依存追加やデータ移行はなく、互換性を保つ規約改善としてpatch versionを更新します。

## 検証と確認限界

- Codex／Claude双方の追加節の一致、差分check、既存の参照経路を確認しました。
- 独立したread-onlyレビューで、推測的対策と必要な安全対策、検証境界、関数分割、例外処理の文書上のケースを確認し、指摘はありませんでした。
- Codexの既存hook出力に開発guideへの参照が残ることを確認しました。source・test・Skill・hookの変更はありません。
- 文書上のケース評価はruntime行動の実証ではありません。live配置、新規sessionでの自然な適用、出力品質改善は未確認です。

本版は配布資産の公開です。端末localへの配置は含まず、実設定・認証・Memory・共有記録・外部管理Skillを変更しません。
