# v7.3.0

共通の作業規約を、[依頼と操作権限の入口](https://github.com/natumekazuki/.codex/blob/9749a8f1e26da26f86464c6ee1f7eca43b1a93de/AGENTS.md)と作業別の判断基準に整理します。報告では、依頼への答えと、受入や利用に影響する失敗・未確認・残件を伝えます。依頼外で行わなかった操作の列挙は求めません。

## 変更内容

- **実装を残すか、どこで担うか。** [設計ガイド](https://github.com/natumekazuki/.codex/blob/9749a8f1e26da26f86464c6ee1f7eca43b1a93de/docs/guides/design-decisions.md)では、まず仕組みを外すとどの要求を満たせなくなるかを考えます。責務が必要なら、フロント・バックそれぞれで既にその役割を担う部品やサービスを優先します。長く保守する同じ業務判定は一か所で変更できるようにし、画面での入力支援とサーバー側の認可、使い捨ての処理まで共通化しません。
- **UIに説明を足すとき。** [UI基準](https://github.com/natumekazuki/.codex/blob/9749a8f1e26da26f86464c6ee1f7eca43b1a93de/docs/guides/ui.md#主内容と補助説明の境界)では、補助枠を先に作らず、配置や操作名で伝わらない場合だけ、対象画面・状態・最短の文案と理由をまとめて実装前にユーザーの明示承認を求めます。新たな但し書きなら一語のバッジや一時通知でも同じです。読み上げ名、重大操作の対象・影響、失敗後の回復手段は補助説明ではなく、機能の一部として提供します。
- **変更したtestを残す基準。** [変更testのガイド](https://github.com/natumekazuki/.codex/blob/9749a8f1e26da26f86464c6ee1f7eca43b1a93de/docs/guides/test-changes.md)では、旧パネルを消した事実は今回の差分や描画で確かめ、非公開項目を返さないなど将来も守る契約はtestに残します。Python／TypeScript／C#のtestを追加・意味変更・削除・移設したときは、従来どおりGit差分から抽出した対象を削除側も含めて独立したread-only審査へ渡します。
- **WithMateで作業を分担するとき。** 担当の選定・相談・報告・成果の受入は[協同ガイド](https://github.com/natumekazuki/.codex/blob/9749a8f1e26da26f86464c6ee1f7eca43b1a93de/docs/guides/withmate-collaboration.md)、通常子の専用Worktreeの配置・回収は[作業領域ガイド](https://github.com/natumekazuki/.codex/blob/9749a8f1e26da26f86464c6ee1f7eca43b1a93de/docs/architecture/subagent-workspace.md)にまとめます。親が起動前に作業場所を用意し、子は共有記録を更新するだけでなく、成果を直属の親へ届けます。

## 互換性・更新時の注意

`review-test-value` のCLI・構造化出力・metadata v2・対応言語・Git差分選択の契約は変わりません。`templates/plan.md` と `templates/architecture.md`、完了済みの抽出器のMVP計画は配布から外します。旧雛形を参照する手順がある場合は参照を見直してください。ADRとreviewの雛形は固定欄ではなく任意の記入例になります。

手動コピーで更新する場合は、[配置手順](https://github.com/natumekazuki/.codex/blob/9749a8f1e26da26f86464c6ee1f7eca43b1a93de/README.md#配置と検証)に沿って、`~/.codex/` 配下の共通入口とガイド、利用中のSkill・native role・hookを同じ版に揃えてください。Skillはホストの探索先、native role・hookは有効な `CODEX_HOME` が配置先です。配布版のモデル指示を使う場合は `model_instructions_file` の参照先も更新します。端末の `config.toml` を配布例で置き換える必要はありません。
