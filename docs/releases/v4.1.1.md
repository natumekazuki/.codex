# natumekazuki/.codex v4.1.1

`review-test-value`のGit差分抽出で、対象外binaryの混在によるUTF-8 decode失敗と、Windowsでdecode例外が発生しても成功終了する問題を修正しました。

## 修正

- [Git差分選択](https://github.com/natumekazuki/.codex/blob/ab10d379020bab388d9139c9a3693e4e04a9f2a8/skills/review-test-value/scripts/git_diff_selection.py)は、対象言語の拡張子で変更pathを選択してからraw textのhunkを取得します。対象外binaryの追加・変更・削除が混在しても、対象testの抽出を妨げません。
- Gitと[native adapterの実行](https://github.com/natumekazuki/.codex/blob/ab10d379020bab388d9139c9a3693e4e04a9f2a8/skills/review-test-value/scripts/extract_test_values.py)は、pipeの出力をbytesで受け取り、呼出元でUTF-8を厳密にdecodeします。Windowsのreader thread内だけでdecode例外が発生し、呼出元が成功を返す経路を除きました。adapterのstdoutだけでなくstderrのdecode失敗も非成功になります。
- 対象source自体の読取・decode失敗は、既存の診断またはCLIエラーとして非成功を返します。sourceの不正byteを無視したり、置換文字で補ったりして正常な抽出結果として扱いません。

## 互換性と範囲

- CLI、構造化result、metadata v2、対応adapter、snapshot semanticsと[Git差分選択契約](https://github.com/natumekazuki/.codex/blob/ab10d379020bab388d9139c9a3693e4e04a9f2a8/skills/review-test-value/references/git-selection-v1.md)を維持するpatch releaseです。対象sourceに対するraw text diffは引き続き取得します。
- recordの対応付けアルゴリズムは変更していません。一意な根拠がある場合の`SURVIVED`と、曖昧な場合の`RECORD_TRANSITION_UNRESOLVED`を維持します。元の報告にあった2件の対応付け失敗は旧新source・hunk・利用版が未提供であり、原因確定・修正済みとは扱いません。
- 利用先アプリケーションや端末のSkill配置は変更していません。既存のSkill配置方法で更新する必要があります。
