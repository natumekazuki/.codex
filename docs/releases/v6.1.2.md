# v6.1.2

WithMateのSession間で、受け手が参照できないファイルパスを渡す問題へのルール修正です。

## 変更内容

[共有基準](https://github.com/natumekazuki/.codex/blob/1343d3c6b1f606700020a1b8256ab7a6a86d8b53/docs/guides/withmate.md)に、通常送信での半角`@`付き絶対パスを定めました。範囲外で拒否された場合は必要な共有資料だけを双方が利用できるCrew Folderへ配置し、参照を差し替えます。既に参照可能なファイルは移動せず、repositoryの正本・ユーザー原本・他者の作成物は保護します。[review保存方針](https://github.com/natumekazuki/.codex/blob/1343d3c6b1f606700020a1b8256ab7a6a86d8b53/docs/guides/development.md)は初期保存と共有段階を区別しました。

## 互換性

指示の互換修正です。Skill・CLI・配置入口・Session Graph契約、認可境界は変更しません。WithMate本体・実設定・認証は更新対象外です。

## 確認範囲

3製品の変更箇所と参照整合、差分検査を確認しました。WithMateのCodex通常親子Sessionで、親と子それぞれのSessionFolderのファイルを半角`@`付き絶対パスで相手へ送信し、両方向とも`SESSION_REJECTED / effect: none`となることを確認しました。子から親への検査は受信側Full Accessでも拒否されました。

これは通常送信の範囲外検査の実測です。新ルールによる自律的な共有先選定、Crew Folder配置後の配送、Claude/OpenCode固有modelの応答を実測したものではありません。
