# 変更testの審査と保持

残すのは、現在も必要な振る舞いを守るtestである。旧パネルを消した事実だけなら、今回の差分や実描画で確認して終える。そのための恒久test・fixture・metadataを先に作らない。一方、「権限のない利用者には非公開項目を返さない」は、表示や内部実装を替えても有効な契約である。不在という期待値の形だけで、どちらも同じ扱いにしない。

恒久testの価値は、現役の要求・契約、違反による具体的な影響、既存の型・check・testでは検出できない故障、CI・保守の負担が見合うかで判断する。削除・非表示後も不在を継続して保証する理由は、該当metadata・review記録・PR説明のいずれかで分かるようにする。一時検証が必要なら目的を果たした時点で終了し、`ephemeral` のtestは `remove_when` を満たしたら除く。

既存の機構が不要なら、それだけを支えたtest・fixture・metadataも同じ論理変更で整理する。testがあるという理由で実装を戻さず、逆に失敗を消すために現役の保証を弱めない。

Python／TypeScript／C#のtestを追加・意味変更・削除・移設するときは、作業途中で選んだ変更も含め、変更前にruntimeの `review-test-value` Skillを読む。タスク開始時のbaseから決定論的に抽出し、削除側も含む全対象を独立した通常のread-onlyサブエージェントが専門審査する。抽出・審査と必要なtest実行は別の確認である。
