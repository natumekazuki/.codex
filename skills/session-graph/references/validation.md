# 変更対象別の検証

本書はSession Graphの仕組みを改修・配置・移行するときに使う。変更対象に対応する節で確認範囲を選び、通常のmmd更新では[Skill本文](../SKILL.md)の内容・保存結果を確認する。描画確認はユーザー指示時のみとし、変更と無関係な試験や、影響を受けない成功済みの確認は繰り返さない。

## Skill指示の変更

変更した指示と参照元を照合し、共通AGENTS.mdの権限境界、Skillの読書き・表示の契約、hookの利用契機との整合を確認する。参照・呼出経路を変える場合は、その影響先をたどる。文言だけの変更でrepository全体の探索や配置試験まで広げない。

行動を変える指示は、影響する判断を含む代表的な依頼で試す。受信から記録・更新・復元までのうち変更した経路を対象にし、期待結果はSkill本文の該当契約と照合する。例えば帰属の変更なら他主体を含む共有図、Iconの変更なら提供された画像と名前を使う。完成済みの図を読むだけで先行記録の遵守を確認した扱いにしない。表記・参照のみの修正は差分とリンクの確認にとどめる。

図の表示修正・確認をユーザーから指示された場合の描画とプレビューの後片付けは、[Skill本文](../SKILL.md#ユーザーへ見せる確認する)に従う。[共有入口](../assets/index.mmd)・[説明例の更新](../assets/instruction-update.mmd)は主体と版・静的reviewと実行・局所確認と統合／公開、[比較資料](../assets/comparison.mmd)は条件・置換理由・確認の限界、[説明更新の範囲変更](../assets/scope-change.mmd)・[共有契約](../assets/shared-contract.mmd)は判断変更・依存の架空例であり、変更に合う例だけ使う。

情報の置き方を変える場合は、評価対象へ改善後の指示・図・復元質問を渡し、期待回答は照合側だけで使う。主体、必須条件、変更・追加できない対象、以前の判断と置換理由、確認対象・範囲、未実施／未確認、参照名だけで内容の確認を成立させていないかを照合する。入力文字数・読込対象数・参照の追加負担と、図の読みやすさは別に評価し、文字数減だけで認知負荷や復元精度の改善を断定しない。必要な例に確認を限定し、通常更新へ全例の試行や常時描画を追加しない。

## 保存helperの変更

保存・後片付け処理を変更した場合は既存testを実行する。指示文やmmdだけの変更では実行しない。

```powershell
python -X utf8 -m unittest discover -s skills/session-graph/scripts -p "test_*.py"
```

対象pathとsnapshotの一致、原文保持、競合検出、置換失敗時の旧内容保持、ロック解放が維持されるかを変更箇所に照らして確認する。複数図の保存経路を変える場合は、詳細だけ保存された状態から最新内容を失わず再開できるかも確認する。Windows／Linuxの実行・skipを区別し、helperの成功を図の意味・読みやすさの保証にしない。

後片付けの変更では、指定入力だけの削除、正本・lock・別の入力の保持、範囲外・リンク・対象不一致の拒否、読取のみと既にない入力、削除失敗の報告を確認する。保存後の後片付けと、保存失敗・競合で再適用に使う入力の保持を混同しない。

## runtime配置

配置を行う場合だけ、現在のruntimeが探索する場所へ既存のコピー／link方式で`skills/session-graph/`全体を配置する。共通AGENTS.mdは`~/.codex/`、hookは有効なCodex homeを使い、無関係なconfig・他Skillを上書きしない。

新規sessionでSkillの実path・発見・重複と、変更した指示の適用を確認する。hook・探索・復元経路を変更した場合は、影響するstartup／resume／手動・自動Compactで提供済みSessionFolderの入口へ到達できるかを確認する。hook変更時は`/hooks`でtrustと重複も確認し、[Codex Hooks](https://developers.openai.com/codex/hooks)・[Codex Skills](https://developers.openai.com/codex/skills)の契約を利用バージョンに照合する。`PreCompact`のstdoutに記録保存を依存させず、`Stop`を追加しない。

## 既存記録の移行

単一の`SessionFolder/session-graph.mmd`等を移す場合だけ、対象SessionFolder・利用者・更新停止の調整・旧図の処置と権限を確認する。Skill改修は移行や旧図削除の承認ではない。

1. 旧図の最新版から、要求・制約・判断経緯・主体・根拠・未確認を新しい入口と話題図へ対応付ける。既存の参照切れも区別する。
2. helperで詳細 → 入口の順に保存する。切替前に旧図の更新有無を照合し、競合・部分保存はSkill本文の手順で扱う。
3. 旧図との情報保持と、新しい入口からの復元を確認する。描画確認の条件はSkill本文に従う。初運用の原資料がなければ架空例の確認と実資料の未確認を分ける。
4. 確認後、承認された旧図の処置を行う。削除未承認なら保持し、新正本の所在と書込み元の切替状況を報告する。

## 結果の扱い

実施した確認・結果・影響範囲の未確認を既存の作業報告へ簡潔に残す。静的な照合、モデルの試行、実描画、runtimeでの実効確認は区別する。対象外の試験は残件にせず、配布元の改修だけでruntime反映や実セッション動作を確認済みとしない。新しい恒久の検証台帳は作らない。
