# 配置・受入確認

本Skillと保存helperの変更・配置時に必要な範囲で行う。配布元のtest成功を、runtimeへの配置・モデル動作・人による把握の確認に読み替えない。日常の全タスクへ以下の一式を課さない。

## 関連する定義・経路の確認

repository全体から`session-graph`、共有記録の保存先、必須利用条件、読書き・復元契機を探索し、実際の参照・実行経路をたどる。AGENTS.md、README、共通guide、system prompt編集元、hook／設定／配置script、metadata、テンプレート、helper、例、検証手順のうち関係するものを同じ論理変更で整合させる。列挙した種類がすべて存在・変更対象であるとは仮定しない。

AGENTS.mdは必須契機・事前記録・権限境界と詳細への入口、Skillは読書き・競合・復元、hookは短い再通知を担う。物理的な単一ファイル指定や手順の二重定義を残さず、履歴として保持するADR・リリースノートを現行指示へ書き換えない。利用先repositoryの独自指示が影響を受ける場合は対象を説明し、無断で一括更新しない。

## 配置

`skills/session-graph/`を現在のruntimeが探索するSkill置き場へ既存のコピー／link方式で配置する。`SKILL.md`だけでなく`agents/`、`assets/`、`scripts/`、`references/`を揃える。共通AGENTS.mdは`~/.codex/`、hookは有効なCodex homeへ配置し、`/hooks`で変更後のtrustと重複を確認する。実SessionFolderのpathを設定に固定せず、既存config全体・他Skillを上書きしない。

新規sessionの一覧で実path・発見・重複を確認する。`UserPromptSubmit`と`SessionStart`のstartup／resume／compactで入口が届くことを確認する。hookにSessionFolderの独自フィールドを仮定せず、現在の提供済みSession情報（WithMateでは`# SessionFolder`）から解決する。手動Compactとターン途中の自動Compactを区別し、同じ入口・今回の話題・必要な依存図を復元できるか確認する。

`PreCompact`のstdoutに意味内容の保存を依存させず、`Stop`を追加しない。hook発火自体は記録の正しさを証明しない。hookや探索の契約を変更する時は[Codex Hooks](https://developers.openai.com/codex/hooks)と[Codex Skills](https://developers.openai.com/codex/skills)を利用バージョンに照合する。

## 既存記録の移行

単一の`SessionFolder/session-graph.mmd`等を移す時だけ行う。配布元の改修を移行の実施・削除承認とみなさず、対象SessionFolder、実際の利用者、更新停止の調整、旧図の処置と操作権限を確認する。他セッションの一括移行・削除や自動migrationは行わない。

1. 旧図の最新版を読み、要求・制約、判断の転換と理由、実施・検証・未確認、外部参照を新しい話題図へ対応付ける。完了した経緯を一律に削らず、古い現状は当時の判断と区別する。対応確認は作業中に行い、別の恒久台帳を作らない。
2. 話題図をhelperで保存してから入口を保存する。旧図の内容が移行中に変わっていないか原文を照合し、変わっていたら差分を反映してから切り替える。全fileのtransactionを保証した扱いにしない。
3. 入口から関連図を読む復元と、旧図との情報照合・実描画を確認する。参照先が削除・移動・正本化されていたら関係するものを直す。確認できない根拠は未確認として明示する。
4. 移行確認後、承認された旧図の処置を行う。削除未承認なら削除せず、新正本の所在と旧図が残っている状態を報告する。旧図を黙って現行の第2正本にせず、書込み元の切替・未調整を分ける。完了済みのリリースや整理自体を再開扱いにしない。

## 保存helper

```powershell
python -X utf8 -m unittest discover -s skills/session-graph/scripts -p "test_*.py"
python -X utf8 -m py_compile skills/session-graph/scripts/session_graph.py
```

固定フォルダー直下の対象指定、対象外path／リンクの拒否、snapshotと保存先の一致、原文・改行保持、同内容の無変更、同じ図の同時作成・競合exit 3、別図の独立更新を確認する。置換失敗後の旧内容保持、ロック待ち打切り、プロセス中断後の解放も確認する。

詳細保存後に入口保存が失敗・競合したケースでは、詳細の保存は維持され、入口と詳細を再読して未保存分だけ再適用できることを確認する。全体rollbackや複数file一括成功を前提にしない。Windows／Linuxの実行環境とリンクtestのskipを区別して報告する。正本の意味・読みやすさはこのtestの対象ではない。

## モデルとユーザー向け表示

指示を記録するところから代表ケースを試す。既に完成した図を読めることだけを、先行記録の遵守と扱わない。安全な作業領域で行い、削除等は架空の状態更新と実操作を区別する。

| ケース | 確認 |
| --- | --- |
| 配置・禁止・対象外・数値・例外を含む依頼 | 依存作業前に条件が残り、ユーザー要求とAI案が分かれる |
| 複数の独立話題と一部依存 | 入口から現在の話題・結論・未決定／未確認・詳細所在を特定でき、関係のない全図を読まなくても復元できる |
| 話題切替・無変更の再開 | 移る先の制約・未解決を読む。現在の話題変更は入口へ反映し、読むだけの再開で不要な保存はしない |
| 訂正・一部撤回・追加 | 無関係な要求を失わず、旧条件を現在も有効として残さない |
| 当時は保持 → 容量確認 → 追加承認 → 削除 → 結果確認 | 当時の判断と変更理由を追え、現在の削除済み状態・未承認範囲・受入未決定が区別できる |
| 失敗で新条件が判明／実装済み・未検証から再開 | 成功結果を待たず条件を保存し、未検証を完了にしない |
| 設計相談／read-only review | 記録だけの許可をソース・外部writeへ広げない |
| MainとAuxiliaryの共有更新 | 最新snapshotから双方の条件を保持して再適用する。古いdraftへsnapshotだけ付け替えない |
| 詳細保存直後の中断／入口未作成・未登録話題 | 固定フォルダーの対象を特定し、最新詳細を失わず入口を同期する |
| 手動／自動Compact、resume | 要約だけでなくSkill→入口→話題→必要依存から復元する |
| 消失・読込不能・不正ファイル・保存失敗 | 空図で隠さず、未記録の指示に依存する作業だけ止める |
| 未完了あり／対象外の会話 | 前者は未確認を記録して終了し、後者は不要なファイルを作らない |

[入口の例](../assets/index.mmd)、[環境整理](../assets/storage-cleanup.mmd)、[公開](../assets/release.mmd)は架空の表現例であり、例の数値・承認・成果物は実績ではない。既存ローカルMermaidレンダラーで、入口を開き詳細へ進む流れを確認する。SVGやpreviewでリンクが動くか、PNGでも関係・所在が読めるかを別に見る。リンクが使えなければその制約を報告し、表示pathで辿れることを確かめる。

入口の最初の表示に現在の話題が現れるか、結論と未確認が識別できるかを見て、ソースの記述順だけで判断しない。詳細は要求から現状までの判断理由、当時／現在の区別、正本・実装・後続対応・検証根拠の関係を確認する。長いラベル・線の交差・読めない縮小・情報の欠落を直し、同じ最新版を再確認する。構文成功やスクリーンショット取得だけで済ませない。

初運用の実図が提供されている場合は、許可されたコピーで入口と話題図へ整理し、旧図との条件・経緯・参照の対応と描画を照合する。原資料がなければ架空例での確認と初運用例の未確認を分け、確認済みとしない。表示経路がない場合も未実施として残し、専用viewerの新設や未承認のinstallを代替手段にしない。

実施結果、未実施の環境・経路、配布元改修／runtime反映／移行の各状態は既存のPR・作業報告へ簡潔に残す。新しい恒久の採点基盤・監査・別台帳は作らない。
