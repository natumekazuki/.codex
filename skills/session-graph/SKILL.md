# Session Graph

**指示を受ける → 最新記録を読む → 条件を記録・照合する → 作業する → 結果を更新する。**

AIの復元と、ユーザーによる「言ったこと・現在地・依存関係」の確認に同じ記録を使う。Main／Auxiliaryは区別しない。

## 入口と保存先

- 対象は、SessionFolderが提供された開発・調査・設計・review。雑談や単発の一般説明へ記録を強制しない。対象作業中の訂正・追加条件は短い発言でも対象。
- runtimeが通知した本Skillの実pathから読む。共有先は現在の提供済みSession情報（WithMateではプロンプトの`# SessionFolder`）の絶対pathとし、`session-graph.mmd`を1つだけ置く。Workspace、thread ID、配布元checkout、`CODEX_HOME`から推測しない。
- 開始・再開・Compact後は、現在のSession情報から同じpathを解決し、本Skillと**最新のファイル**を読み直す。会話要約や前回読んだ写しだけで再開しない。取得できなければ既存の提供経路を確認し、解決不能の範囲を報告する。別Folderへの新設や全会話ログの探索で代用しない。
- 初回の未作成と、再開時の消失・破損・読込失敗を区別する。再開時に期待した記録がなければ復元を確認し、空図で上書きしない。
- 共通AGENTS.mdの許可範囲で、記録と更新用一時ファイルだけを操作する。記録は実装・外部操作の承認ではない。ファイル変更自体を禁じたユーザー指示とruntime権限を優先する。

## 受信時に記録するもの

独立して満たす条件を分け、ユーザーの言葉に近い具体的な短いラベルにする。「〜しない」「〜だけ」「今回は対象外」「〜と同じ」「〜より先に」、適用範囲、例外、数値を落とさない。曖昧なら未決定として保存できる。全設計の完成を記録の前提にしない。

ユーザー要求とAIの設計案・推測を分ける。相談中の提案を採用済みにしない。訂正時は古い条件を有効なまま併記せず、関係する判断・実装・検証を見直す。延期・撤回は判断元と短い理由を残し、達成しやすくするために要求を消さない。

記録後、今回の発言に含まれる各条件がどこにあるか照合してから依存する作業へ進む。例：「ActionDockの上」「高さ変更」「既存と同じ最大化」「xterm.js利用」「独自実装を避ける」を「ターミナル追加」1項目へ潰さない。記録に必要な読込・最小限の解釈確認は先に行ってよい。転記の確認をユーザーへ毎回押し戻さない。

## 図の書き方

初期形式はUTF-8のMermaid `flowchart`。Markdownのコードフェンスで包まない。[表現例](assets/example.mmd)を見て、**例の要求や状態はコピーせず**、その作業の内容に置き換える。正本は1つであり、JSON／Markdownの別管理簿を並行更新しない。別形式を採用する判断は、記録・共有・復元だけでなく、ユーザーの確認負担も同等以下であることが条件。

| 項目 | 表し方 |
| --- | --- |
| 要求・制約 | `R_配置`等の安定IDと具体的な条件。否定・例外を見えるラベルに残す |
| 設計判断 | `D_分割方式`等。採用／未決定と短い理由を付け、対象へ結ぶ |
| 作業 | `I_配置`等。要求 → 作業を「実現」で結ぶ |
| 検証 | `V_配置`等。何を確かめたかと未実施／成功／失敗／要再確認。作業 → 検証を「検証」で結ぶ |
| 未解決事項 | `Q_終了時`等。未解決であることと、影響する対象を示す |

- 機能・操作ごとにsubgraphで要求と対応を近くへまとめる。分類別の巨大な列や、全クラス・全テストの写しを作らない。独立した追跡が不要な情報までノード化しない。
- 辺は「実現」「検証」「依存」「影響」等の意味を付ける。作業の依存は「依存する側 → 必要な側」とし、実行順と混同しない。記録できたことを、実装や検証ができたことにしない。
- 状態は短い文字と視覚表現を併用する。例の`todo`／`active`／`implemented`／`verified`／`blocked`を使えるが、色だけで区別しない。実装済み・未検証と検証成功を分ける。
- 長文を箱へ詰めない。短くするのは説明であって条件ではない。大事な条件をコメントや参照先だけに隠さない。詳細結果は既存成果物への参照でよい。
- 根拠は対象IDの直近に`%% V_配置: 対象commit / 確認内容 / 結果への参照`等で残し、図にも結論を表示する。ログ全文や別の証跡台帳は作らない。機密path等を外部レンダリングサービスへ送信しない。
- ノードIDの重複、未定義ノードへの辺、状態の文字と装飾の食い違いを確認する。quoted labelと必要なエスケープを使う。Mermaidを独自の正規表現だけで完全検証した扱いにしない。

## 更新・復元

設計変更はその判断に依存する作業より先に、実装・検証の結果はその区切りで保存する。次のユーザー入力やCompact直前まで持ち越さない。影響する設計・コードが変われば既存の検証を要再確認に戻す。要求本文を状態変更のついでに要約し直さない。

ターン終了・引継ぎ・完了報告前に、受けた指示と結果が同期しているか確認する。未完了があってもターンは終了できる。未完了を消す、全件完了まで待つ、終了チェックのためだけに継続を繰り返す運用にはしない。変化がなければ書き直さない。

グラフは作業の現在地を持つ。製品の契約、実コード、Issue、ADR、正式な検証結果は既存の正本へ参照でつなぐ。グラフと実コードが食い違えば調査し、グラフだけを根拠に完了しない。独立した監査をこの記録手順へ組み込まず、作業履歴をrepositoryへ恒久保存することも強制しない。

## 共有ファイルの保存

[保存helper](scripts/session_graph.py)を使う。Python 3.10以降の標準ライブラリだけで動く。全セッションが同じ手順を使い、正本への直接の上書き編集は行わない。

```powershell
# $skillRoot: runtimeから取得した本Skillの絶対pathのディレクトリ
# $folder: 現在の提供済みSessionFolderの絶対path
python -X utf8 "$skillRoot/scripts/session_graph.py" snapshot --session-folder "$folder"
```

戻り値の`content`が最新グラフ、`snapshot_path`がその読込内容を保持する一時ファイル。`exists: false`はファイル未作成であり、初回だと確認できた場合だけ新規作成に使う。snapshot JSONを編集しない。正本ではなく、次の保存との比較にだけ用いる。

1. 最新内容を読み、その内容から自分の変更だけを加えたdraftをSessionFolder直下の衝突しない一時名で作る（例：UUIDを含む`.mmd`）。要求の抽出と描画確認はロック外で行う。
2. 次を実行する。

```powershell
python -X utf8 "$skillRoot/scripts/session_graph.py" save --session-folder "$folder" `
  --snapshot "<返されたsnapshot_path>" --input "<自分のdraftの絶対path>"
```

3. 成功時は保存した指示と結果を確認し、自分のsnapshotとdraftだけを削除する。他セッションの一時ファイルを一括削除しない。続けて編集する時は新しいsnapshotを取得する。

exit `0`は保存／読込成功、`3`は競合、`2`は入出力・形式・ロック待ち等の失敗。競合時は最新snapshotを読み、自分の変更だけを再適用する。古いdraftのままsnapshotだけ差し替えて再保存しない。相手の訂正と矛盾したら未解決として扱い、自動的にどちらかを捨てない。失敗した保存を成功と報告せず、その指示に依存する作業だけを保留する。

helperは保存時に原文を比較し、同一ディレクトリ内で一時ファイルを原子的に置換する。OSの短時間ロックを使い、既定5秒（最大30秒）で待機を打ち切る。推論や実装中にロックは保持しない。`.session-graph.lock`は空の制御用ファイルとして残す。使用中に削除しない。異常終了時はOSがロックを解放する。

保証範囲は同じhelperを使うローカルプロセス間。直接編集や、排他・置換が保証されないネットワーク／同期ドライブを安全だと仮定しない。helperの形式検査はflowchartの外形のみであり、全構文・条件の網羅性・人間の読みやすさの証明ではない。

## ユーザーへ見せる・確認する

現在の正本を既存のローカルMermaid表示手段で描画する。利用できるMermaid対応preview、または導入済みの`mmdc -i <graph> -o <preview.svg>`を使い、同じ最新版を見せる。画像は再生成可能な表示結果であり、編集する正本にしない。表示手段を勝手にインストールしたり、専用ビューアを開発したりしない。

描画を見て「条件を見つけられる」「何が未検証か分かる」「依存先をたどれる」を確認する。線の交差、長文、読めない縮小、過密な図は構文が成功しても修正する。小さな変更ごとに不要な全文説明や図の貼り直しをせず、必要な場面で最新版への参照と変更箇所を短く伝える。表示環境がなければ記録・作業は続けられるが、視覚確認は未実施と明示し、ソースの読解をユーザーへ押し付けて代替しない。

配置・受入確認は[検証手順](references/validation.md)を参照する。日々の全タスクへ検証一式を追加する指示ではない。
