# Session Graph

**指示を受ける → 入口と関連図の最新版を読む → 条件を記録・照合する → 作業する → 結果を同期する。**

ユーザーが要求・判断・経緯・現在地・関連先を把握する図と、AIが制約・理由・未完了を復元する記録を共用する。Main／Auxiliaryは区別しない。保存する情報量と、一度に読む・表示する範囲を分ける。

## 入口と保存先

- 対象は、SessionFolderが提供された開発・調査・設計・review。雑談や単発の一般説明へ記録を強制しない。対象作業中の訂正・追加条件は短い発言でも対象。
- runtimeが通知した本Skillの実pathから読む。保存先は現在の提供済みSession情報（WithMateでは`# SessionFolder`）の絶対pathから解決した`SessionFolder/session-graph/`。Workspace、thread ID、配布元checkout、`CODEX_HOME`から推測しない。
- 同フォルダーの`index.mmd`を入口にし、独立して追跡・更新する必要のある話題を`storage-cleanup.mmd`等の意味の分かる名前で分ける。小さい関連話題は同じ図のsubgraphでよい。ターン・日付ごとの分割、多数の空図の先行作成、ファイル数・ノード数・文字数の一律上限は設けない。
- 共有記録は入口と話題図の集合であり、物理ファイル1つという意味ではない。Graphと同じ情報を持つJSON／Markdownの別台帳、人向けとAI向けの二重管理は作らない。reviewの詳細・指摘別の対応状況は下表の結果文書を正本とし、Graphは要約と参照を担う。画像は再生成可能な表示結果であり正本ではない。
- 初回の未作成と、再開時の消失・破損・読込失敗を区別する。期待した記録がなければ提供経路と復元を確認し、空図や別Folderで代用しない。既存の単一図がある場合は[移行・配置の確認](references/validation.md#既存記録の移行)に従い、未移行を未作成とみなさない。
- 共通AGENTS.mdの許可範囲で記録と自分の更新用一時ファイルだけを操作する。記録は実装・外部write・破壊的操作の承認ではない。変更禁止の明示指示とruntime権限を優先する。他セッションの図や利用先repositoryの規約を一括変更しない。

## 何をどこへ残すか

| 配置 | 責務 |
| --- | --- |
| `index.mmd` | 現在扱う話題、各話題の短い結論・未決定／未確認、話題間の関係、詳細図のファイル名。追記日記にせず現在地を更新する |
| 話題別mmd | 要求・制約、調査、判断の転換と理由、作業・検証結果・未解決の流れ。入口と要求・経緯の全文を二重管理しない |
| `SessionFolder/review-results/*.md`（ユーザー指定時はその保存先） | review結果と指摘別の判断・対応・確認結果。保存・再読・更新は共通AGENTS.mdから解決した`~/.codex/docs/guides/development.md`の「SessionFolderのreview記録と対応管理」に従う。Graphには結論・未解決の要約とファイル・必要な指摘IDへの参照だけを置く |
| repositoryのADR・Issue・ソース・正式な検証結果 | 製品契約・実装・残件・根拠の既存正本。グラフへ移管・全文複製しない |

入口では現在扱う話題を起点として見つけやすくし、完了話題は必要な接続先として残せる。詳細には、次がなければ現在の結論・範囲・未確認の意味が分からなくなる情報を残す。

- 要求と適用範囲、除外・否定・例外・数値。「〜だけ」「〜と同じ」「〜より先に」等を一般的な一語へ潰さない。
- 判断理由、前提・採用範囲が変わった点、後継判断との関係。
- 実際の実施・検証結果と、未実施・未確認・受入判断の違い。
- 詳細の正本、根拠、後続対応の所在。

ユーザー要求とAI案・推測を分け、相談中の提案を採用済みにしない。曖昧な条件は未決定として記録でき、全設計の完成を待たない。受信内容の各条件がどこに残ったか照合してから依存作業へ進む。必要な読込・最小限の解釈確認は先に行ってよい。転記確認を毎回ユーザーへ戻さない。

現在の状態は安定IDの既存ノードを更新する。判断変更では、前の判断を「当時」「撤回」「置換」と明示し、後継判断と変更理由へ結ぶ。古い条件を有効な制約として併記せず、影響する作業・検証を見直す。完了しただけで経緯を要約・削除せず、全コマンド・全ログ・同じ結果の反復も保存しない。セッション内の経緯保持を製品repositoryの作業ログ恒久保存へ広げない。

## 読む・書くタイミング

| 契機 | 読む対象 | 保存する対象・時点 |
| --- | --- | --- |
| 開始・再開・Compact後 | 本Skill → 入口 → 今回の話題 → 判断に必要な依存先。現在のSession情報と最新ファイルを使い、会話要約で代用しない | 復元のみなら更新不要。差異・不足が判明した部分だけ扱う |
| 新しい指示・追加条件・訂正 | 入口と関係する話題の最新版 | 依存作業の前に条件・範囲・訂正を話題図へ記録・照合する |
| 話題の切替 | 移る先の制約・未解決と必要な依存図 | 現在扱う話題が変わったら入口を更新する |
| 判断の確定・変更 | 関係する要求・根拠・影響先 | 判断を使う作業の前に理由・影響を話題図へ保存。現在の結論が変われば入口も更新する |
| 調査・実装・検証の区切り | 更新対象の最新版 | 判断材料・状態・結果が変わった時に保存する。長い作業でも終了まで持ち越さない |
| 終了・引継ぎ・完了報告前 | 今回の要求と更新した記録を照合 | 書き漏れ・未確認と入口の現在地を同期。変化がなければ書き直さない |
| 保存競合 | 最新の更新対象と変更の影響先 | 自分の変更だけ再適用。古いdraftに新snapshotだけ付け替えない |

tool callごとではなく、要求・判断材料・状態の変化を区切りとする。失敗で続行条件や見立てが変わった場合も記録し、重要な新条件の保存を次の成功まで待たない。設計・コードが変わって確認範囲に影響すれば検証を要再確認に戻すが、記録更新だけのために成功済み検証を繰り返さない。

図の読取と参照先の実状態の検証は別である。図だけで実装・検証・承認・完了を成立させない。未完了を残してターンを終了でき、同期のためだけの継続や監査の自動起動は行わない。

## 図と関連先の表し方

UTF-8のMermaid `flowchart`をコードフェンスなしで保存する。[入口の例](assets/index.mmd)と[話題図の例](assets/storage-cleanup.mmd)を参照し、例の要求・状態を実作業へコピーしない。

- 要求`R_範囲`、判断`D_削除範囲`、作業`I_削除`、検証`V_容量`、未解決`Q_受入`等の安定IDを使う。機能・操作ごとのsubgraphで近くにまとめ、全クラス・全testの写しを作らない。
- 辺には「実現」「検証」「置換理由」「判断の正本」「後続対応」「実装対象」「検証根拠」等の意味を付ける。依存は「依存する側 → 必要な側」とし、実行順と混同しない。話題をまたぐ依存にも相手の図名と対象を見えるノードで示す。
- 状態は短い文字と装飾を併用する。実装済み・未検証と検証成功を区別し、色だけに頼らない。長文を箱へ詰めず、重要条件・判断理由・関連先をコメントだけに隠さない。文字数やノード数を人／AIへ固定配分しない。
- 外部正本は表示ラベルに名前と参照可能なpath・Issue番号等を添え、対象との意味付き辺で結ぶ。現在の参照と判断時点の参照を区別する。branch・commit・確認範囲等の復元補足は対象IDの近くへ短く添え、巨大なコメント欄を別の主記録にしない。
- `click`は補助として使えるが、PNGでも何との関係か・どこを参照するか読めるようにする。実際のviewerで動作を確認し、相対pathの基準やリンク許可を全viewerで同じと仮定しない。リンクを動かすためにviewerの安全設定を緩めない。
- 参照先の削除・移動・正本化が分かったら、当該記録を更新・整理する区切りで関係する参照を修正する。削除済みのログは「当時確認・ログ削除済み」等と区別し、現存する根拠へ誘導しない。全参照の毎ターン再検証は要求しない。
- ID重複、未定義ノードへの辺、文字と装飾の状態不一致を確認し、quoted labelと必要なエスケープを使う。独自の正規表現だけでMermaid全構文を検証した扱いにしない。

## 共有ファイルの保存

[保存helper](scripts/session_graph.py)を使い、正本を直接上書き編集しない。Python 3.10以降の標準ライブラリのみで動く。`--graph`には固定フォルダー直下のファイル名を明示し、絶対path・サブフォルダー・リンク先を指定しない。

```powershell
# $skillRoot: runtimeが通知した本Skillの絶対pathのディレクトリ
# $folder: 提供済みSessionFolderの絶対path
python -X utf8 "$skillRoot/scripts/session_graph.py" snapshot --session-folder "$folder" --graph index.mmd
python -X utf8 "$skillRoot/scripts/session_graph.py" snapshot --session-folder "$folder" --graph storage-cleanup.mmd
```

返された`content`が対象の最新版、`snapshot_path`が読込内容を保持する一時ファイル。snapshot JSONは正本でなく比較用であり編集しない。`exists: false`を初回作成に使うのは未作成と確認できた場合だけとする。

1. 最新内容から自分の変更を加えたdraftをSessionFolder直下の衝突しない一時名（UUID等）で作る。条件抽出・推論・描画確認はロック外で行う。
2. 読み取った対象と同じ`--graph`、そのsnapshot、別のdraftを指定して保存する。

```powershell
python -X utf8 "$skillRoot/scripts/session_graph.py" save --session-folder "$folder" --graph storage-cleanup.mmd `
  --snapshot "<返されたsnapshot_path>" --input "<自分のdraftの絶対path>"
```

3. 保存結果を確認し、自分のsnapshotとdraftだけを削除する。続けて編集する時は新しいsnapshotを取得する。他セッションの一時ファイルを一括削除しない。

exit `0`は成功、`3`は原文の競合、`2`は入出力・形式・対象不一致・ロック待ち等の失敗。同内容の保存は`changed: false`で置換しない。競合時は最新を読み、自分の変更だけ再適用する。相手の訂正と矛盾したら未解決として扱い、自動的に片方を捨てない。失敗を成功扱いせず、未記録の指示に依存する作業だけ保留する。

helperはsnapshotの保存先一致と原文を比較し、対象と同じディレクトリの一時ファイルから1ファイルを原子的に置換する。SessionFolder単位のOSロックは保存・読込の短時間だけ保持し、既定5秒・最大30秒で打ち切る。`.session-graph.lock`は制御用として残し使用中に削除しない。プロセス中断時はOSが解放する。

### 複数図の更新・中断からの再開

全体のtransactionや自動rollbackはない。参照される詳細図を先に保存し、最後に入口の結論・詳細所在を更新する。新しい図へ分割する時も新図 → 参照元の順に保存し、参照を切り替える前に既存図を削除しない。

詳細だけ保存されて中断した場合、再開時に入口と関係する詳細の最新版を読み、結論・未確認・接続先の差を照合して入口の更新だけを完了する。初回作成や新話題の追加で入口にまだ現れない場合は、固定フォルダー内のmmd名を確認して対象を読む。入口が欠けた場合も空の新規記録とは決めつけない。逆に入口が存在しない詳細を指していたら参照不整合として扱い、取得・復元できるまでその内容を成立済みにしない。

保存済みの他ファイルを古い内容へ戻さず、未保存の対象ごとに最新snapshotから再適用する。入口と詳細の短い結論・未確認・所在の一致を更新責任者が確認する。保存成功の件数を全図の整合保証に読み替えない。

保証範囲は同helperを使うローカルプロセス間。直接編集、保存中の外部からのpath差替え、排他・置換が保証されないネットワーク／同期ドライブを安全と仮定しない。形式検査はflowchartの外形だけであり、全構文・条件網羅・読みやすさを証明しない。

## ユーザーへ見せる・確認する

既存のローカルMermaid preview、または導入済み`mmdc -i <graph> -o <preview.svg>`で最新版を描画する。機密path等を外部レンダリングへ送らず、表示手段を無断導入・専用viewerを開発しない。

ブラウザーを使う場合は共通`AGENTS.md`の非表示原則に従い、起動前にheadless／非表示設定を確認する。リンク遷移を含む確認中も勝手に可視表示へ切り替えず、生成したスクリーンショット等の描画を実際に見る。非表示で確認できない範囲は未確認として残し、表示が必要なら事前に確認する（表示の明示依頼がある場合を除く）。

入口の最初の表示で現在の話題・結論・未決定／未確認・詳細所在が分かるか、関連図で条件・判断変更理由・未検証・正本との関係をたどれるかを実際に見る。ソース先頭への追記を描画位置の保証にせず、交差・過密・読めない縮小・長文を見直す。必要な経緯を削って入口の小ささだけを達成しない。

不要な全文説明や図の再掲をせず、必要な場面で入口と変更した話題への参照を短く伝える。表示手段がなければ記録・作業は続けられるが視覚確認は未実施とし、ソース読解をユーザーへ押し付けて代替しない。変更・配置の受入時は[検証手順](references/validation.md)を読む。日々の全タスクに検証一式を追加する指示ではない。
