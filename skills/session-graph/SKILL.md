# Session Graph

Crewの作業を引き継ぐ人が「何が今も有効で、何を根拠にどこから続けられるか」を判別できるようにする。現在のSession-bound MCPを使い、共有先は保存されたCrew所属からWithMateが解決する。起点・通常子孫Main・各MainのAuxiliaryは同じGraph、Standaloneは所属Auxiliaryと一つのCrewを使う。WorkspaceやCharacterで共有先を選ばない。別Crewの明示読取は書込先・担当・権限を変えない。

利用契機・記録の許可は共通入口 `~/.codex/AGENTS.md`、呼出・値・上限・認可は現在のMCP instructions・schemaに従う。独自の台帳、子ごとのコピーや接続設定を作らない。Graphは操作承認・実行証拠・親への配送を代替しない。

## 現行条件を復元する

開始・再開・Compact後は本Skillを読み、`list_topics` と検索語なしの `recent` で話題と直近の変化を把握する。次に該当話題の `context` で現行要求・制約・採用判断・未解決・未完了を確かめる。委譲では指定された話題・recordから始め、ユーザーの目的と自分の担当を分ける。

判断に必要なrecord・関係は `get` で、具体的な文言は `search` で確認する。要約された外部端点だけで判断せず、必要な本文・参照先の正本まで読む。部分取得から不存在や削除を推定しない。完全性が判断を左右する範囲は同一revisionの続きも取得し、途中でrevisionが変われば該当箇所を取り直す。継続中は変更に関係する範囲で足りる。復元のみで状態が同じなら書き戻さない。

## 依存作業の前に条件を保存する

- 要求・制約・承認の追加や訂正を受けたら、関連記録を読み、操作・対象・範囲・例外を保存して受信内容と照合してから依存作業へ進む。採用判断の確定・変更も、理由・影響先を保存してから適用する。
- 調査・実装・検証の区切りでは、対象・revision・条件と観測した結果を残す。静的確認・実行・review・統合・公開は同じ状態ではない。根拠が成立しなくなった範囲は要再確認とする。話題切替・終了・引継ぎでは完了範囲、残件と必要な参照を更新する。
- 同じ話題・事実には同じIDを使う。担当（`actor`）、内容の由来（`origin`）、採否の由来（`adoptionOrigin`）、初回記録者（`recordedBy`）を分ける。提案をユーザーが採用しても元の提案者や担当は変わらない。提案・採否、作業進捗、検証結果、論点の解消をそれぞれの状態で扱う。
- `title` は要点、`detail` と `scope` は理由・条件・適用範囲。否定・限定・数値・順序を落とさない。証拠は `references` で正本を指す。reviewは結論・未解決と結果ファイル・必要な指摘IDへの参照で足り、指摘ごとの対応やraw logを写さない。非公開の自然文の表現は `~/.codex/docs/guides/withmate.md` に従う。

## 同時更新と結果不明

書換え前に対象を読み、未変更の必須本文・属性・他者の進行状態を保つ。読み取ったrevisionで、記録と意味のある明示的な関係を同じatomic applyにまとめる。kindや採否を変える時は不要になる状態や由来を、MCPの保持・解除契約に沿って扱う。関係の向き・stable IDを守り、話題・時刻・担当の一致だけで関係を作らない。孤立記録は正しく、関係を張っても状態は自動で変わらない。

判断の置換・撤回では元の本文と当時の理由を残し、`validity` と後継記録・根拠ある関係を一緒に保存する。保存結果と必要なread-backを照合する。記録の保存成功と、参照先の状態や検証成功は別である。

| 状況 | 次に確かめること |
| --- | --- |
| revision競合 | 対象と影響先を再読し、他者の変更を含めてbatchを組み直す。古い内容のrevisionだけ差し替えない。矛盾が残れば未解決とする |
| 保存の応答喪失 | 同じIDを再取得して内容を照合する。結果不明のまま成功・未保存のどちらにも決めない |
| MCP・必要な記録が利用不能 | 未確認・未保存の条件に依存する箇所だけ保留する。独立作業は続け、引継ぎや判断に影響する不足を伝える |
