# Design UI Information

利用者がこの場で何を読んだり見比べたり操作したりするかを起点に、情報と表現を選ぶ。適用・承認・画像共有の基準はユーザーhomeの `~/.codex/docs/guides/ui.md`、固有の語彙・部品・表現方針は対象製品の規約に従う。

## 主役を決める

明示された要求と提供された内容から、何を主役にするかを決める。記事なら本文を読み進める順序、作品集なら作品と解説の関係、比較なら同時に見たい共通項目、制作ツールなら対象と操作の対応に着目する。読む・眺めることが目的の画面に、操作ボタンが必ず要るわけではない。主内容の理解に必要な説明・識別番号・比較材料を長さだけで補足に落とさない。

補助要素を除いた状態で何に困るか考える。作品に補足がなければ、その欄も「補足なし」も要らない。行ごとの操作対象が分かりにくければ、操作を該当行に寄せて「名前を変更」と示せる。同じ場所に「右のボタンで編集できます」を重ねる理由はない。詳細表示は後で読む価値がある情報のために使い、今必要な情報を隠したり、不要な情報の退避先にしたりしない。新たな補助説明の採否はUIガイドで判断する。

## 関係を配置と表現にする

API・DBの分類や部品単位ではなく、一緒に読むもの、比べるもの、操作対象と結果をまとめる。近接・整列・余白・文字の強弱で、最初に目に入るものと、その次に読むものの関係を作る。表、グリッド、縦並び、別ページなどは同時参照の要否と読む順序で選ぶ。カードの数やページ高は目標にしない。狭い幅でも対応関係を保ち、短くするために作品の面積や本文の可読性を犠牲にしない。

文字の大きさ・行長、画像の比率・切り抜き、余白・色・動きは、内容と製品の表現方針に合わせる。承認済みの規約と適切な既存画面を参照し、同じ役割には既存の部品・token・語彙・操作の慣習を優先する。見た目が似ていても別の責務を無理に一部品にせず、頻出するだけの不適切な表現も広げない。表現方針が未定なら今回の主内容に必要な選択をし、製品全体の新規規約にはしない。

## 状態が違えば、次にできることも違う

検索が成功して0件なら、条件を変える手掛かりを示せる。取得に失敗したなら件数は不明であり、0件とは表示せず、失敗した対象、保持された入力、可能な再試行などを伝える。未取得・権限不足・部分取得と全件取得も区別する。補助機能だけの失敗は影響する場所に置き、主内容まで使えないように見せない。不明な原因や計測していない進捗を作らない。

削除・公開などでは、確定前にどの対象がどう変わるかと、取り消せるかを伝える。「注意」や色だけでは影響は伝わらない。失敗や結果不明を成功表示で覆わない。仕様が定まっていない重大操作を、必須文言の名目で実装側が決めない。

見出しと読む順、画像の代替、操作名、状態の読み上げを内容に対応させる。キーボードで対象に到達・操作でき、フォーカスが見え、一時表示を閉じて戻れるかを見る。十分なコントラストを保ち、色の差・動き・hoverだけに依存しない。見える文字を減らすために曖昧なアイコンに置き換えない。

## 変わった体験を実画面で確かめる

影響する画面・状態へ許可された経路で到達し、実際の表示を製品の基準画面と見比べる。主内容を読み進めたり、一件選んで操作したりして、前後のつながり、スクロール途中の対応関係、表示の切れや不要な往復を確認する。長い名称、狭い幅、文字拡大、失敗時などは、変更で崩れ得る条件を選ぶ。通常時に消した補助の代わりに、安全や回復に必要な意味まで消えていないかは、必要な状態を実際に起こして確認する。

遷移・フォーカス移動・動きは操作して結果を見る。誤字修正ならその箇所と影響を見ればよく、全画面の監査を足さない。修正後は影響範囲を再確認し、利用者が見る実画像をUIガイドに従って共有する。
